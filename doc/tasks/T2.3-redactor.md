Acceptance criteria:
- Key matching:
  - Normalized key substring matching against `sensitiveKeys` across case variations and non-alphanumeric separators.
  - Token splitting at non-alphanumerics, camelCase, and acronym boundaries matching `sensitiveKeyTokens`.
  - Avoids false positives for short words (e.g., `shipping`, `spin`, `wildcard`).
  - Covers documented false positives (`secretary`, `tokenizer`, `cardType`) and false negatives (`data`).
- Value patterns:
  - Replaces regex matches on string fields with `replacement` (`[REDACTED]`).
  - Does not scan map keys by value patterns (documented limitation).
- Bounded scan window:
  - Discards text beyond `maxScanChars` (2 * fieldCap) prior to pattern replacement.
  - Truncates secrets straddling the scan window edge along with discarded characters.
- Fail-closed handling:
  - Catching exceptions during redaction replaces field with `[REDACTION_ERROR]` without throwing into host code.
- Build mode policy:
  - Redaction can be disabled (`enabled: false`) in debug mode.
  - Redaction cannot be disabled when running in release mode (`BuildMode.isRelease`), forcing redaction active.
- Sensitive data isolation:
  - Sentinel secret is replaced in nested maps and maps inside lists without leaking.
