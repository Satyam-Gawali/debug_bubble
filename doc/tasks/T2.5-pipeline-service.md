# T2.5 — DebugLogService Pipeline & Console Sink
Status: Done
Phase / depends on: P2 / T2.2, T2.3, T2.4
Scope: Implementation of the central logging pipeline (`DebugLogService`) and console collector (`ConsoleSink`) with gates, sanitization, entry creation, fan-out, and failure isolation per ARCHITECTURE.md §2 and DATA_MODELS.md §9.
Prerequisites: T2.2 (bounded store), T2.3 (redaction engine), T2.4 (bounded payload conversion).
Expected file changes: lib/src/core/debug_log_service.dart, lib/src/collectors/console_sink.dart, lib/src/core/debug_bubble_controller.dart, test/unit/service/service_test.dart, test/unit/service/console_sink_test.dart
Acceptance criteria:
- Pipeline gates:
  - Enabled gate: `enabled: false` causes logging to be a silent no-op.
  - Build-mode gate: Release builds (`BuildMode.isRelease`) cause logging to be inert.
  - Active controller gate: Disposed or inactive controllers do not log.
  - Minimum level gate: Severity levels below `config.minLevel` are dropped (D-11); they never enter the store, do not increment `droppedCount`, and produce no console output.
- Payload sanitization & entry creation:
  - Ingestion runs payload sanitization and redaction prior to entry creation.
  - Generates monotonic sequence IDs per controller, starting at 1, which are preserved across `clear()`.
  - Normalizes timestamps to UTC.
  - Preserves truncation status on created `DebugLogEntry`.
- Bounded store fan-out:
  - Accepted entries are added to the controller's `DebugLogStore`.
  - Triggers controller listener notifications upon ingestion.
- Console sink:
  - Formats plain text blocks per DATA_MODELS.md §9 (header with timestamp, level, tag/subTag, (#id), and `(truncated)` suffix when truncated).
  - Emits formatted logs via `debugPrint` and `dart:developer.log`.
  - Can be turned off via `config.consoleOutput: false`.
  - Test seam provided via `ConsoleSink.testListener`.
- Sentinel secret non-retention:
  - Sentinel secrets in message, tag, error, metadata, and JSON never appear in the store or in console output.
- Failure isolation (NFR-03):
  - Logging never throws into host application code even if toString(), iterators, or console sinks throw.
