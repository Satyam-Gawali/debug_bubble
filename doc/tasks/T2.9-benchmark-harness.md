# T2.9 — Benchmark Harness Skeleton
Status: Done
Phase / depends on: P2 / T2.5, T2.7, T2.8
Scope: Create a minimal, repeatable benchmark harness under `test/performance/` to measure core engine throughput, payload conversion overhead, redaction impact, high-volume eviction, and export serialization per SECURITY_PERFORMANCE.md §6.
Prerequisites: T2.2 (store), T2.3 (redactor), T2.4 (payload sanitizer), T2.5 (service pipeline), T2.7 (exporters).
Expected file changes:
- `test/performance/benchmark_runner.dart` (new)
- `test/performance/core_benchmark_test.dart` (new)
- `doc/tasks/T2.9-benchmark-harness.md` (new)

Acceptance criteria:
- Lightweight benchmark harness:
  - Zero third-party dependencies; uses Dart/Flutter built-ins (`Stopwatch`, `Platform`).
  - Warmup iterations followed by timed execution rounds.
  - Computes operations per second and average latency per operation (microseconds).
  - Reports environment metadata: OS, OS version, Dart version, build mode, and timestamp.
- Core engine benchmark scenarios (SECURITY_PERFORMANCE §6):
  - Scenario 1: Small entry ingestion throughput and timing (1,000 iterations).
  - Scenario 2: Large message truncation and budget enforcement (10,000 char messages).
  - Scenario 3: Complex payload sanitization (nested structures, 50-item lists, cyclic object references).
  - Scenario 4: Redaction overhead:
    - Baseline (redaction disabled).
    - Standard sensitive key matching.
    - Sensitive keys + 3 regex value patterns (card numbers, emails, bearer tokens).
  - Scenario 5: High-volume burst and ring-buffer eviction overhead (2,000 entries into 500-capacity store).
  - Scenario 6: Export serialization overhead (`exportJson` and `exportText` across 1,000 entries).
- Public API and production code integrity:
  - Zero modifications to production source code or public API in `lib/`.
  - Informational only: no hardcoded performance claims or unvalidated thresholds committed (as required by SECURITY_PERFORMANCE §6 and Gate G2).
